当前人工内容审核与作品核验同步写库后回包，不await截图或模型；自动重审仅enqueue，背景自动审核才执行截图和模型。因此没有证据把人工提交的等待归为模型计算。列表只返回资源URL，不携带模型/图片二进制。预览SHA缓存在Linux可复用静止文件，Windows重新读取计算；本地表现不能直接替代生产耗时。

其余源码发现：

- remembered只校验账号代次，未按同path请求先后保护缓存（platform.js:343–348）；页面丢弃旧响应时它仍可能已经覆盖缓存。受控实测较新响应标题为Newer server title，旧响应迟到后recall变回Probe work 0。
- 审核GET没有默认超时，错误区域没有直接重试；一次挂住的读取可持续保持首次载入（platform.js:289–297、account.js:1107/1604）。建议仅给相关GET增加超时与明确重试，保持上传等待行为。
- 切审核tab重新mount，新建筛选/排序/选择状态；仅作品搜索与题目参数从URL恢复（app.js:1794–1806、account.js:1091–1093）。普通审核刷新保留现有state，不能泛称每次刷新都会丢表单。
- api迟到401未核对请求开始时的accountGeneration，可在切换账号后清空当前身份（platform.js:308–316）。这是源码确认的竞态，本轮未浏览器复现。
- 有元数据修正的单件核验先meta再review，两次写请求独立；核验接口本身已支持多数元数据，note/promptVariant仍需meta。应由独立后端明确同事务接口后再合并，不能只删除前端meta请求。
- 批量核验每件构造临时完整form（account.js:1421–1425）；work-fields.js:28–39重复统计全站模型/工具/档位并生成选项。可复用本次快照统计并直接复用字段规则校验，保持逐项失败反馈。

审核弹窗当前仅截图与新标签打开作品链接，没有内嵌iframe；弹窗挂在document.body，列表draw不会必然刷新弹窗。因此不建议将该链路的卡顿归为批量iframe加载。
