## 本轮目标与决定

用户要求核实并修复真实问题。核查中用户明确要求竞猜部分「先不管这个」，因此 V-01/V-04/V-05 的规则和源码未改。用户另行允许只追加 Gallery HANDOFF，保留其他会话的未提交记录；提交只收本轮安全修改。

报告不是 47 个已证实的可利用漏洞。它混合了真实缺口、旧版本行为、正常设计、依赖未来功能的假设和信息项。尤其竞猜数据不进入盲评 Elo；作品不同源时 `allow-same-origin` 保留的是作品自己的源，不能因此读取父页面；多表情和已注销用户历史票也不能直接套报告的数据库建议。

## 已实现的修复

- V-08：验证码验证、邮箱绑定、密码重置共用每 IP 30 次/分钟的独立桶，带 Retry-After，不与登录/注册混桶。
- V-09：安全兼容 `TRUST_PROXY=loopback` 与 `1`；空值/0 关闭，其他值启动报错。实际 IP 仍只信本机代理追加的最后一个有效地址。未取得生产值，不能确认线上是否有单桶故障。
- V-10：人机验证通过后才占用全局密码计算并发额度。保留密码计算的资源上限，失败的挑战不再长时间占住名额。
- V-07 的条件性配置缺口：Turnstile 只配一把密钥时失败关闭；两把都未配置保留开发环境禁用模式。注册仍使用发码时已验证的人机挑战和一次性邮箱码。
- V-11：Gallery `?v=` 与 version.json 使用 HTML/JS/CSS/运行配置的内容哈希，公开 data.json 去掉 frontendCommit。数据包兼容标识保留，不改变消费契约。
- V-13/V-14：两个前端构建后的内联启动代码和 Gallery import map 使用 SHA-256 CSP 哈希，最前面的 meta 策略禁止任意内联脚本/事件；保留 Cloudflare 验证和 Blob Worker。Nginx 原响应头与 meta 取限制的交集，头里仍有 unsafe-inline 也不会重新放开脚本。后台主题启动移到外部 JS，后台响应头直接去掉脚本 unsafe-inline。
- V-18：只记录已知页面与实际存在的题目路径，随意字符串不再进入后台热门路径。匿名访客统计仍是近似数据，不能宣称阻断了所有伪造浏览量。
- V-20/V-21：后台相机与 Gallery 盲评折叠消息同时核对当前 iframe 窗口和源；发送使用明确目标源。相机向量只接受有限数值的三元数组。
- V-23：作品内容服务统一增加 HSTS，包括错误响应；作品已有的 CSP 保留。
- V-29：内容服务错误页 title/detail 做 HTML 转义。
- V-32：六个完整目录 GET/HEAD 接口携带不支持的 limit/offset/page 明确返回 400 unsupported_pagination；不擅自分页破坏现有消费者。
- V-17：新增待安装的 SSH 密钥认证配置模板；没有安装到生产服务器。

## 规范依据

- [MDN：CSP 多策略同时生效](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy#multiple_content_security_policies)：新增策略只能继续收紧，不能被较宽的响应头重新放开。
- [MDN：iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox)：不同源 iframe 的 allow-same-origin 不改变它与父页面的同源关系。
- [Debian CVE-2026-3497 跟踪](https://security-tracker.debian.org/tracker/CVE-2026-3497)：Bookworm 修复版本为 1:9.2p1-2+deb12u9，涉及发行版 GSSAPI 补丁；banner 不代替实际包/配置核查。
