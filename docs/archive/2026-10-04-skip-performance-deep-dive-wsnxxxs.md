## 已确认的路径

`site/arena.js:523` 的 `prefetch()` 在成功选择后抽下一组；`vote()` 的 skip 与正常投票都进入此路径。桌面在两个当前作品旁再挂两个 `.is-next` iframe。`site/platform.css:415` 仅做 CSS 隐藏，作品没有暂停协议；`sp-arena` 消息折叠控件，不停止渲染。`next()` 会删除当前层并显示预取层。

本轮找到的具体重作品是古建筑题的 Seed-2.1-Pro。其体素创建函数 `ue()` 每次都新建 BoxGeometry、MeshLambertMaterial 和 Mesh，所有这些网格都投射、接收阴影；`Io()` 持续安排 requestAnimationFrame，更新控制器并调用 `Yt.render(Fn, Wt)`。实测每帧约 4.4 万次 WebGL 绘制调用，包含阴影等渲染通道，不能把该数字当作体素数量。

在模拟线上同注册域、不同子域的环境中，这件作品即使 CSS hidden 也持续渲染。它在下一组被提前创建时，当前画面就一起降帧；点击下一组只是把它从隐藏变为可见，因此负载继续。换掉包含它的那一组后，本轮观察到性能恢复。这是一条已复现的症状路径，尚不能断言报告人当时隐藏的也正是 Seed。

### 为什么普通本地测试会漏掉

同一浏览器、相同源码与探针，仅改变主页面和作品的域名关系：

- 主页面 `localhost`、作品分别为独立的 `TOKEN.localhost` 时，隐藏作品 rAF 为 0。
- 主页面 `gallery.perf.localhost`、作品为 `TOKEN.w.perf.localhost`，模拟线上同注册域不同子域时，隐藏作品 rAF 继续。
- 用下一组与当前完全不同的 Qwen Max / GPT-6.1 做 A/B 重测也成立：跨站点隐藏耗时为 0，同主域隐藏回调约 180 次/秒、合计约 41 ms/s；暂停归零、恢复再次出现。因此不依赖重复挂载同一件作品。

这只是当前 Codex Browser/Chromium 环境的实测差异，不将同站点、跨源、进程分配混为一谈，也不承诺所有 Chromium 配置一定如此。浏览器可能节流隐藏 iframe，CSS 隐藏本身不提供可靠的作品暂停契约。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API) 说明 CSS 隐藏 iframe 不改变子文档的可见性状态；[Chromium Site Isolation 说明](https://new.chromium.org/developers/design-documents/site-isolation/) 区分 site 与 origin。

## 其他核对与边界

- 固定顺序连续十一组覆盖二十一件不同作品，含正常模拟投票、第五与第十组跳过停留、再下一组。iframe 数量仍按 2 → 4 → 2 变化；移除重作品后恢复。没有得到旧 iframe 无界累积的证据，但不是完整内存泄漏审计，也没有验证该固定序列的生产随机配对或软冷却行为。
- 较早的相同重作品重复预载实验也观察到约 280 → 520 ms/s，暂停后约 262，恢复约 507；该实验用于控制变量，不能作为生产下一组的真实抽取序列。后端正常候选充足时回避上一组作品，最终结论以上述不同作品实验为依据。
- 梵境古刹本身有持续渲染开销与短时 worker 建模，但本例持续低帧阶段 worker 已结束。跨站点隐藏 rAF 暂停的实验还观察到首次显示时约 150 MiB 的累计 bufferData 上传及约 300 ms 的长任务；这是另一种首显卡顿，不能混成同主域持续高耗时的主因，也不是总显存占用估计。
- 未发现折叠消息持续风暴或 Gallery 配对循环无界运行的证据。浏览器日志有 Three.js 既有弃用、阴影回退及 shader 精度警告，没有捕获相应的脚本异常循环。
- 本机为 Core Ultra 5 245K / RTX 5070 Ti。没有报告人的原始配对记录或 CPU 火焰图，不能把本地约 990 ms/s 直接换算成原截图 99.9%。截图的八个 Document frames 和 327 MB 也不足以单独证明泄漏。

## 决策

本轮保持调查范围，不改参评作品或正式功能。建议优先把桌面预加载改为只预取配对数据，用户进入下一组时再创建作品。这样可避免尚未选择查看的重作品拖慢当前页；本例已验证该缓解方向，同时明确它不会让 Seed 本身变轻。

重作品进入可见状态后的性能应另行评估；若要调整实例化、合并网格、材质复用或阴影，应走作品所属私有数据的维护流程，不能在 Gallery 提交资源副本或擅自改写参评结果。需要保留运行级预加载时，再讨论明确的暂停/恢复支持。
